# Técnicas de UX/DCU <span class="badge badge-new">Novo</span>

O projeto de IHC não trata só de acessibilidade. Esta página reúne técnicas de **UX** e de **Design Centrado no Usuário (DCU)** que ajudam a entender quem usa o produto, o que essas pessoas vivem e como a organização sustenta essa experiência.

## Personas { #personas }

Personas são representações arquetípicas do público-alvo, criadas a partir de dados reais extraídos de pesquisas e entrevistas. Elas personificam grupos de clientes com comportamentos, dores e motivações semelhantes.

- **Composição:** uma persona típica recebe um nome fictício, uma foto, dados demográficos, uma biografia curta, seus principais objetivos e suas maiores frustrações (*pain points*).
- **Aplicação em UX:** servem para alinhar a equipe de produto. Em vez de projetar para um genérico “público-alvo de 25-40 anos”, a equipe projeta para a “Mariana, que trabalha estudando à noite e tem pouco tempo para interfaces complexas”. Isso direciona a tomada de decisão com base na empatia.

## Jornadas do usuário (*User Journeys*) { #jornadas }

A jornada do usuário é o mapeamento visual do caminho, passo a passo, que a persona percorre para atingir um objetivo específico com o produto ou serviço (por exemplo, desde a descoberta de uma necessidade até a compra e o uso contínuo).

- **Fases do processo:** divide-se em etapas cronológicas (descoberta, consideração, compra, retenção, etc.).
- **Pontos de contato (*touchpoints*):** onde o usuário interage diretamente com a marca, como um anúncio no Instagram, a interface do aplicativo ou o SAC.
- **Curva emocional:** a parte mais importante do mapa. Registra o que o usuário pensa e sente em cada etapa, ajudando a localizar os picos de frustração (fricções) e os momentos de encanto.

## Blueprint de serviços (*Service Blueprint*) { #service-blueprint }

Se a jornada do usuário mostra a perspectiva e a emoção do cliente, o *Service Blueprint* revela os **bastidores da empresa** necessários para que essa jornada aconteça de forma fluida. É a ponte estrutural entre a experiência do cliente e as operações de negócio.

O blueprint é organizado em camadas separadas por “linhas de visibilidade e interação”:

| Camada | O que representa | Exemplo |
|---|---|---|
| **Ações do cliente** | O passo a passo exato extraído da jornada do usuário. | Escolher o prato e pedir a conta. |
| **Frontstage** (palco visível) | Funcionários ou tecnologias com os quais o cliente interage diretamente. | Atendente de caixa, portal de autoatendimento, aplicativo. |
| **Backstage** (bastidores) | Processos e funcionários que o cliente não vê, mas que são cruciais para a entrega. | Cozinheiro preparando o prato; sistema verificando o limite do cartão. |
| **Processos de suporte** | Estruturas que sustentam toda a operação. | Bancos de dados, integrações de TI, sistemas legados, logística de terceiros. |

## Canvas (*UX Canvas* / *Lean UX Canvas*) { #canvas }

O UX Canvas é um framework visual de uma única página, adaptado do tradicional *Business Model Canvas*, desenhado para estruturar projetos de forma rápida, ágil e focada no usuário.

- **Estrutura:** mapeia o problema de negócio (o que a empresa precisa resolver), os resultados esperados (*Business Outcomes*), as personas, as necessidades do usuário (*User Outcomes*), as hipóteses a serem validadas e as ideias de solução.
- **Vantagem:** substitui documentações de requisitos longas e burocráticas por uma visualização colaborativa. Permite que as partes interessadas de negócios, tecnologia e design cheguem a um consenso rápido sobre o escopo e o propósito de um produto antes de desenhar a primeira tela.

## Design empático { #design-empatico }

O design empático não é apenas uma ferramenta, mas uma **mentalidade de pesquisa**. A premissa central é que os usuários, muitas vezes, não conseguem articular exatamente o que desejam, porque se acostumaram a criar adaptações (“gambiarras” ou *workarounds*) para lidar com fluxos ineficientes.

- **Observação vs. pergunta:** em vez de perguntar ao usuário, em uma sala de reuniões, “Como você usa esse sistema?”, o designer vai até o ambiente natural dele (a casa, a fábrica, o balcão da loja) e observa o comportamento real.
- **Técnicas comuns:** pesquisa etnográfica, entrevistas contextuais e *shadowing* (acompanhar o usuário como uma “sombra” durante a execução das tarefas, sem interrompê-lo).
- **Objetivo:** sentir o contexto real de uso, entender o estresse, o barulho do ambiente e as limitações cognitivas, para criar produtos que resolvam necessidades latentes que nem mesmo o cliente sabia como explicar.
